DocKit 1.1.1：轻量化版本。功能与界面不变，安装包和运行时大幅瘦身，操作更快；另修两个原有问题。

## 轻量化（本机实测，Mac16,12 / Apple M4 / macOS 27.2）

| 指标 | 1.1.0 | 1.1.1 |
|---|---|---|
| 下载 | 77.1 MB | 44.7 MB（-42%） |
| 安装后占用 | 251.8 MB | 132.4 MB（-47%） |
| 包内文件数 | 6,833 | 4,634 |
| 空闲内存（界面进程） | 46 MB | 43 MB |
| 空闲 CPU | 0.06% | 0.07% |
| docx → Markdown 子进程峰值内存 | 128.4 MB | 90.3 MB |

体积与空闲数字均来自两个版本的发布包解压副本；冷启动到窗口出现同一时段交替测量，1.1.0 为 1.28 秒、1.1.1 为 0.96–1.03 秒（5 次中位数，本机负载偏高）。各项操作耗时（直接调用包内后端，与 App 参数相同，3 轮取中位数）：启动时读取操作列表 0.62 → 0.29 秒，docx 规范化 3.1 → 0.8 秒，docx → Markdown 9.9 → 4.1 秒，Excel → txt 4.6 → 2.0 秒，pptx → Markdown 2.1 → 0.7 秒，Markdown → Word 3.1 → 1.2 秒。这组耗时在本机高负载时与发布候选同源的构建上交替测得，绝对秒数偏大，只作前后对比。

改了什么：

- docx → Markdown 不再依赖 magika 与 onnxruntime 模型运行时，改用约 140 行的内容识别替身；16 份真实文档输出逐字节相同，扩展名是 .docx 但内容其实是 HTML、纯文本等的文件仍按内容转换。
- 不再打包 magika、onnxruntime 及只被它们依赖的库（约 84 MB），以及各库自带的测试目录、类型存根和头文件、标准库里用不到的 Tk/IDLE/turtle/ensurepip 等（约 38 MB），另去掉没有任何模块导入的 lxml.objectify（约 5 MB）。构建时有导入守卫：随包发出的代码只要还导入被删模块，构建就失败。
- 所有二进制去掉本地调试符号（strip -x）后逐个重新签名。
- 为各项操作实际用到的 1,169 个模块预编译字节码，不再每次操作都从源码重新编译 pandas、python-docx 等。注意：改动包内 .py 后不会自动重新编译。

修复：

- 老版 .ppt 转 Markdown 以前会假显示成功；现在装了 LibreOffice 时先另存为 .pptx 再转，没装就明确失败并提示先另存为 .pptx。格式转换没产出新文件一律算失败，失败行显示具体原因。
- 合并多个 .txt（按列合并成 merged.csv）以前会失败，现已修复。

DocKit 1.1.1: a lightweight release. Features and interface are unchanged; the bundle and runtime are much smaller and operations are faster, plus two fixes.

| Metric | 1.1.0 | 1.1.1 |
|---|---|---|
| Download | 77.1 MB | 44.7 MB (-42%) |
| Installed | 251.8 MB | 132.4 MB (-47%) |
| Files in bundle | 6,833 | 4,634 |
| Idle memory (UI process) | 46 MB | 43 MB |
| Idle CPU | 0.06% | 0.07% |
| docx → Markdown subprocess peak memory | 128.4 MB | 90.3 MB |

Size and idle figures come from extracted copies of both release archives. Cold launch to window, measured alternately in the same period, was 1.28 s for 1.1.0 and 0.96–1.03 s for 1.1.1 (median of 5, machine under load). Operation times (median of 3, calling the bundled backend with the app's own arguments) fell from 0.62 to 0.29 s for reading the operation list at launch, 3.1 to 0.8 s for docx cleanup, 9.9 to 4.1 s for docx → Markdown, 4.6 to 2.0 s for Excel → txt, 2.1 to 0.7 s for pptx → Markdown and 3.1 to 1.2 s for Markdown → Word. These were measured alternately on a build from the same sources while the machine was heavily loaded, so absolute seconds run high; read them as before/after ratios.

- docx → Markdown no longer needs magika and the onnxruntime model runtime; a ~140-line content sniffer takes its place. 16 real documents convert byte-for-byte identically, and files named .docx that are really HTML or plain text still convert by content.
- The bundle drops magika, onnxruntime and libraries only they used (about 84 MB), plus test folders, type stubs, headers and unused standard-library parts such as Tk, IDLE, turtle and ensurepip (about 38 MB), and the never-imported lxml.objectify (about 5 MB). An import guard fails the build if any shipped code still imports a removed module.
- All binaries are stripped of local symbols (strip -x) and re-signed.
- Bytecode is precompiled for the 1,169 modules the operations import, so pandas, python-docx and others are no longer recompiled on every run. Editing a bundled .py will not trigger recompilation.
- Fixed: legacy .ppt to Markdown used to report success without output; it now converts through LibreOffice when installed and otherwise fails with a clear message. Conversions that produce no new file count as failures and show the reason.
- Fixed: merging several .txt files into merged.csv failed.
